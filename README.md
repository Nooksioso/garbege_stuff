# 🗒 Stufftime — журнал учёта рабочего времени

Клиент-серверное приложение для фиксации задач сотрудников **по дате и по часам**.
Сервер хранит данные и отдаёт REST API, клиенты работают в **веб-браузере**.

```
┌──────────────┐   REST API (fetch)   ┌───────────────┐
│ Браузер №1   │ ───────────────────► │               │
│ Браузер №2   │ ───────────────────► │   Node-сервер │ ──► data/stufftime.json
│ … из сети    │ ◄─────────────────── │   порт 8080   │
└──────────────┘                      └───────────────┘
```

## Возможности

- **Журнал-таблица** с 5 столбцами: **Дата** (календарь), **Сотрудник**, **Задача**, **Часы**, **Комментарий**.
- **Добавление строк** — кнопка «+ Добавить строку», Enter сохраняет.
- **Корректировка** — кнопка ✎ превращает строку в редактируемую, ✓ сохраняет, ↩ отменяет.
- **Удаление старых записей** — кнопка ✕ (в два клика, со страховкой «точно?»).
- **Справочник сотрудников** — отдельный раздел: внесение, редактирование (✎), удаление (✕); в таблице сотрудник выбирается из справочника; хранится в отдельном файле <code>data/employees.json</code>; у каждого сотрудника можно выбрать готовую аватарку из папки <code>public/avatars</code> (6 картинок) — без аватарки показываются цветные инициалы.
- **Пароль у сотрудника** — поле в справочнике (не короче 4 символов): хранится только в виде хеша (scrypt + соль), в списке показан как 🔒.
- **Экран входа** — поле «Логин» с выпадающим списком сотрудников из справочника + пароль; сессия живёт 8 часов, кнопка «Выйти»; защита от перебора (5 неверных попыток — пауза на минуту); галочка «только мои» в фильтре журнала.
- **Роли** — «администратор» (все записи, справочник, управление ролями, ввод записей за кого угодно) и «исполнитель» (видит только свои записи, вносит новые за себя; справочник скрыт). Роль задаётся в справочнике; **Иванов Сергей — администратор**, остальные — исполнители.
- **Боковая панель (администратор)** — разделы: **Задачи** (таблица записей — основная страница), **Сотрудники** (справочник), **Проекты** (справочник задач). У исполнителя панели нет — только раздел «Задачи». Выбранный раздел запоминается до закрытия вкладки.
- **Справочник «Проекты» (администратор)** — редактируемая таблица: **Номер** (присваивается автоматически — первый свободный; при удалении проекта его номер снова становится свободным), **Наименование** (уникальное для таблицы), **Комментарий** (дополнительная информация). Данные — отдельный файл <code>data/projects.json</code>.
- **Задача — только из справочника «Проекты»**: в журнале задача выбирается из списка проектов — с поиском по наименованию или номеру; ручной ввод отключён (и на клиенте, и на сервере).
- **Подпись внизу страницы** — «Разработка студии «Мусорные Дела»» (на экране входа и в подвале основных страниц).
- **История защищена**: запись хранит «фотографию» имени сотрудника, поэтому удаление человека из справочника не стирает его прошлые записи.
- **Поиск и фильтр** по тексту и по сотруднику; сводка: записей, часов сегодня, часов за месяц.
- **Навигация по неделям (страница «Задачи»)** — таблица показывает записи выбранной недели (понедельник — воскресенье), по умолчанию — текущей. Над таблицей — кнопки «← Назад» и «Вперёд →», между ними — период недели (с какого числа по какое, с пометкой «текущая»). На текущей неделе кнопка «Вперёд» неактивна — на будущие недели переключиться нельзя; назад можно уходить сколько угодно.
- **Темы интерфейса** — светлая (по умолчанию), серая и тёмная; переключатель «Тема» в шапке и на экране входа; выбор запоминается в браузере (localStorage).
- **Логотип** в шапке и на экране входа — `public/logo.png`.

## Запуск

Нужен **Node.js 16+** (`node -v`). Устанавливать зависимости не нужно.

```bash
cd stufftime
node server.js
```

В консоли:

```
  🗒  STUFFTIME — журнал учёта рабочего времени
  локально:   http://localhost:8080
  по сети:    http://<IP-этого-компьютера>:8080
  данные:     /путь/к/stufftime/data/stufftime.json
```

| Откуда | Адрес |
|---|---|
| С сервера | `http://localhost:8080` |
| С другой машины | `http://<IP-сервера>:8080` (откройте порт, см. ниже) |

### Доступ из сети (порт 8080)

- **Windows (admin):**
  ```bat
  netsh advfirewall firewall add rule name="stufftime" dir=in action=allow protocol=TCP localport=8080
  ```
- **Linux (ufw):**
  ```bash
  sudo ufw allow 8080/tcp
  ```

### Настройки

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `8080` | порт HTTP-сервера |

```bash
PORT=9000 node server.js
```

## API (JSON)

Помимо публичных маршрутов входа (`/api/health`, `/api/login`, `/api/login/employees`), все остальные `/api/*` требуют заголовок `Authorization: Bearer <token>`, где токен выдаёт `/api/login`.

Роли (проверяются на сервере): **администратор** — полный доступ; **исполнитель** — видит и изменяет только собственные записи, вносит новые только за себя, управление справочником получает 403.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/employees` | справочник сотрудников |
| `POST` | `/api/employees` | внести сотрудника `{ "name", "role", "accessRole", "avatar"?, "password"? }` |
| `PUT` | `/api/employees/:id` | отредактировать (пустой `password` = не менять; `avatar` — файл из `public/avatars` или пусто; `clearPassword: true` = сбросить) |
| `GET` | `/api/avatars` | список готовых аватарок из `public/avatars` |
| `DELETE` | `/api/employees/:id` | удалить |
| `GET` | `/api/projects` | список проектов — все авторизованные (управление — только администратор) |
| `POST` | `/api/projects` | новый проект `{ "name", "description"? }` — номер присваивается автоматически, первый свободный (только администратор) |
| `PUT` | `/api/projects/:id` | отредактировать проект (только администратор) |
| `DELETE` | `/api/projects/:id` | удалить проект (только администратор) |
| `POST` | `/api/login` | вход: `{ "employeeId", "password" }` → `{ "token" }`; если пароля ещё нет — установка: `"setup": true` |
| `GET` | `/api/login/employees` | список сотрудников для экрана входа |
| `POST` | `/api/logout` | завершить сессию (нужен токен) |
| `GET` | `/api/whoami` | текущий пользователь (нужен токен) |
| `GET` | `/api/entries` | записи журнала (новые сверху) |
| `POST` | `/api/entries` | новая запись `{ date, employeeId, task, hours, comment }` |
| `PUT` | `/api/entries/:id` | корректировка записи |
| `DELETE` | `/api/entries/:id` | удалить запись |
| `GET` | `/api/stats` | сводка (записи, часы сегодня/в месяце) |
| `GET` | `/api/health` | статус сервера |

Задача в записи журнала (`task`) обязана совпадать с наименованием какого-либо проекта — иначе сервер ответит 400: «задачу можно выбрать только из справочника «Проекты»».

Пример:

```bash
curl http://localhost:8080/api/stats
```

## Первый вход

При первом запуске создаются демо-сотрудники — у всех пароль **1234**, **Иванов Сергей — администратор** (все остальные — исполнители).

В уже существующей базе роли проставляются автоматически один раз: сотрудник **Иванов Сергей** становится администратором, остальные — исполнителями. Поменять роль можно в справочнике (✎ → «Роль доступа»); новые сотрудники создаются с выбранной ролью.
Если у сотрудника пароль ещё не задан, его можно установить прямо на экране входа (выбрать сотрудника → «Задайте пароль») — так можно раздать пароли уже существующим сотрудникам. Дальше пароль меняется в справочнике (кнопка ✎), а вход — только по нему. Сессия живёт 8 часов; кнопка «Выйти» завершает её. Токен хранится в sessionStorage браузера (исчезает при закрытии вкладки).

## Данные и сброс

Данные — обычные JSON-файлы в `stufftime/data/`:

- `stufftime.json` — журнал записей и сессии;
- `employees.json` — справочник сотрудников (отдельный файл). При первом запуске после обновления старый справочник из `stufftime.json` переносится сюда автоматически, а сотрудникам без аватара выдаются аватары из готового набора;
- `projects.json` — справочник проектов (задач): номер (присваивается автоматически — первый свободный), наименование (уникальное), комментарий. Создаётся при первом запуске; при первом запуске с демо-данными в него попадают 6 проектов, названия которых совпадают с демо-записями журнала.

- **Сброс к демо-данным:** остановите сервер и удалите файлы `data/stufftime.json`, `data/employees.json` и `data/projects.json`.
- **Резервная копия:** скопируйте эти файлы.

## Аватарки

Готовые аватарки лежат в `public/avatars/` (сейчас 6 шт., SVG). Список формируется сервером автоматически — положите в папку свои картинки (`.svg`, `.png`, `.jpg`, `.gif`, `.webp`) и они появятся в выпадающем списке при внесении/редактировании сотрудника. Сервер отдаёт их как `http://…:8080/avatars/имя_файла`.

## Если браузер говорит «страница не найдена»

1. **Порт занят.** Чаще всего на порту уже работает другая программа — она и отвечает
   «не найдено». Сервер Stufftime при запуске на занятый порт сразу напишет об этом
   в консоли и предложит: `PORT=8081 node server.js`.
2. **Запущен не тот сервер.** Убедитесь, что команда выполняется в папке `stufftime`:
   `cd stufftime && node server.js`. Если `public/index.html` не найден рядом с
   `server.js`, сервер честно напишет об этом в консоли и не запускается.
3. **Открыт не тот адрес.** Локальный адрес — `http://localhost:8080` (не 3000 —
   это порт прежнего приложения).

## Эксплуатация в production (по желанию)

- Автозапуск: `pm2 start server.js --name stufftime` или systemd-юнит (Linux).
- HTTPS: nginx / Caddy reverse-proxy перед портом 8080.
- При росте данных — заменить JSON-файл на SQLite/PostgreSQL; REST-контракт не меняется.
