# 🗒 Garbege stUff — журнал учёта рабочего времени

Клиент-серверное приложение для фиксации задач сотрудников **по дате и по часам**.
Сервер хранит данные и отдаёт REST API, клиенты работают в **веб-браузере**.

```
┌──────────────┐   REST API (fetch)   ┌───────────────┐
│ Браузер №1   │ ───────────────────► │               │
│ Браузер №2   │ ───────────────────► │   Node-сервер │ ──► data/database.json
│ … из сети    │ ◄─────────────────── │   порт 8080   │
└──────────────┘                      └───────────────┘
```

## Возможности

- **Журнал-таблица** с 5 столбцами: **Дата** (календарь), **Сотрудник**, **Задача**, **Часы**, **Комментарий**.
- **Добавление строк** — кнопка «+ Добавить строку», Enter сохраняет. Поле «Сотрудник» новой строки по умолчанию заполняется текущей учётной записью (под которой выполнен вход в систему); администратор при необходимости может выбрать другого сотрудника из списка.
- **Корректировка** — кнопка ✎ превращает строку в редактируемую, ✓ сохраняет, ↩ отменяет.
- **Удаление старых записей** — кнопка ✕ (в два клика, со страховкой «точно?»).
- **Печать (вкладка «Задачи»)** — кнопка 🖨️ «Печать»: таблица записей выбранной недели сохраняется сервером в файл `temporary/raport.csv` (CSV: дата, сотрудник, задача, часы, комментарий; UTF-8 с BOM, разделитель «;»), и браузер предлагает скачать `raport.csv` на компьютер пользователя (содержимое CSV возвращается в ответе API). Администратор печатает все записи недели, исполнитель — только свои.
- **Архив записей** — настройка `archive_day` в `data/setup.json` (значение 8): запись, дата которой на `archive_day` и более дней раньше текущей даты, защищена — добавлять, редактировать (✎), удалять (✕) и переносить на такие даты может только администратор. У исполнителя кнопки неактивны, в строке — отметка 🔒; сервер тоже проверяет и отвечает ошибкой.
- **Справочник сотрудников** — отдельный раздел: внесение, редактирование (✎), удаление (✕); в таблице сотрудник выбирается из справочника; хранится в отдельном файле <code>data/employees.json</code>; у каждого сотрудника можно выбрать готовую аватарку из папки <code>public/avatars</code> (7 картинок, включая енота) — без аватарки показываются цветные инициалы.
- **Пароль у сотрудника** — поле в справочнике (не короче 4 символов): хранится только в виде хеша (scrypt + соль), в списке показан как 🔒.
- **Экран входа** — поле «Логин» с выпадающим списком сотрудников из справочника + пароль; сессия живёт 8 часов, кнопка «Выйти»; защита от перебора (5 неверных попыток — пауза на минуту).
- **Роли** — «администратор» (все записи, справочник, управление ролями, ввод записей за кого угодно) и «исполнитель» (видит только свои записи, вносит новые за себя; справочник скрыт). Роль задаётся в справочнике; **Енот — администратор** (пароль 12345, аватар `raccoon`), остальные — исполнители.
- **Боковая панель (администратор)** — разделы: **Задачи** (таблица записей — основная страница), группа **«Справочники»** — **Сотрудники** (справочник), **Проекты** (справочник задач) и **заготовки для новых справочников — «Должности» и «Заказчики»** (у иконки — пунктирная рамка; по клику открывается страница-заготовка с баннером «🚧 Функционал в разработке» — выводится файл заглушки <code>public/placeholder.html</code>, как на странице «Настройка приложения»), **Отчёты** (столбчатые диаграммы plotly.js), **Настройка** (страница «Настройка приложения» — выводит файл заглушки <code>public/placeholder.html</code> с баннером «Функционал в разработке»). Панель можно **сворачивать вбок** в узкую колонку иконок (кнопка ««/»» в шапке панели; состояние свёрнуто/развёрнуто запоминается в браузере — localStorage <code>stufftime_sidebar</code>; на узких экранах меню горизонтальное и сворачивание не применяется). У исполнителя панели нет — только раздел «Задачи». Выбранный раздел запоминается до закрытия вкладки.
- **Справочник «Проекты» (администратор)** — редактируемая таблица: **Номер** (присваивается автоматически — первый свободный; при удалении проекта его номер снова становится свободным), **Наименование** (уникальное для таблицы), **Комментарий** (дополнительная информация). Данные — отдельный файл <code>data/projects.json</code>.
- **Отчёты (администратор)** — раздел в боковой панели со столбчатыми диаграммами (plotly.js): часы по дням недели и часы по сотрудникам за текущую неделю, данные — из журнала. Библиотека хранится **файлом в составе проекта** — <code>public/vendor/plotly.min.js</code> (plotly.js v4.3.0, https://github.com/plotly/plotly.js): без npm и без CDN, проект переносится на другой компьютер как есть. Если файла нет, сервер скачает его при первом запуске (разово), либо вручную: <code>node tools/fetch-plotly.js</code>.
- **Задача — только из справочника «Проекты»**: в журнале задача выбирается из списка проектов — с поиском по наименованию или номеру; ручной ввод отключён (и на клиенте, и на сервере). Если из списка уже выбран вариант, при повторном вызове списка фильтр очищается и отображаются все проекты (как только начнётся ввод текста — снова поиск).
- **Группировка строк по сотрудникам** — когда в таблице «Задачи» выводятся задачи нескольких сотрудников, строки группируются по Сотрудникам: заголовок группы на каждого сотрудника (по алфавиту), внутри группы — по дате (сначала новые); при выводе одного сотрудника таблица в обычном порядке (по дате).
- **Лимит 24 часа в день** — суммарная длительность задач одного человека за один день не может превышать 24 часов: при создании (и корректировке) записи проверяется оставшееся время за день — и на клиенте, и на сервере (сервер ответит ошибкой, если лимит превышен).
- **Записи только за прошедшие даты** — запрет на добавление записей с датой позже текущей для всех пользователей (включая администратора): при создании (и при переносе записи на будущую дату) сервер отвечает ошибкой, в интерфейсе — подсказка; поле «Дата» в форме ограничено календарём текущей датой.
- **Подпись внизу страницы** — «Разработка студии «Мусорные Дела»» (на экране входа и в подвале основных страниц).
- **Настройки приложения** — JSON-файл <code>data/setup.json</code> (создаётся автоматически при первом запуске): переменная <code>version</code> (сейчас <code>1.1</code>), настройка <code>archive_day</code> (архив записей: дата, на `archive_day` и более дней раньше текущей — защищена от добавления, редактирования и удаления для всех, кроме администратора) и место для будущих настроек; читается публичным API <code>GET /api/setup</code>.
- **Версия внизу страницы** — запись «Garbege stUff ver 1.1» (на экране входа и в подвале): значение переменной <code>version</code> выводится из файла настроек <code>data/setup.json</code>.
- **Номер регистрации в шапке** — «Производственный журнал · рег. № 1.1»: значение переменной <code>version</code> выводится и в шапке приложения (вместо прежнего «рег. № 001»).
- **What's New** — файл <code>Whats New.md</code> с историей изменений (текущий раздел — «Версия 1.1»).
- **История защищена**: запись хранит «фотографию» имени сотрудника, поэтому удаление человека из справочника не стирает его прошлые записи.
- **Поиск и фильтр** по тексту и по сотруднику.
- **Сводка (карточки сверху)** — за выбранную неделю, для текущего пользователя: сколько часов было потрачено на задачи в каждый день недели (Пн — Вс, с датами) и сколько суммарно часов за неделю; при переключении недель карточки пересчитываются. Карточки компактные — все 8 (7 дней + итог за неделю) помещаются в одну линию даже у администратора, с боковой панелью. Цвет карточки каждого дня совпадает с цветом строк таблицы задач за ту же дату (общая палитра d0–d5: фон карточки — как фон строки, цветная полоса карточки — как левый край строки).
- **Навигация по неделям (страница «Задачи»)** — таблица показывает записи выбранной недели (понедельник — воскресенье), по умолчанию — текущей. Над таблицей — кнопки «← Назад» и «Вперёд →», между ними — период недели (с какого числа по какое, с пометкой «текущая»). На текущей неделе кнопка «Вперёд» неактивна — на будущие недели переключиться нельзя; назад можно уходить сколько угодно.
- **Темы интерфейса** — светлая (по умолчанию), серая и тёмная; переключатель «Тема» в шапке и на экране входа; выбор запоминается в браузере (localStorage).
- **Логотип** в шапке и на экране входа — `public/logo.png`.

## Запуск

Нужен **Node.js 16+** (`node -v`). Устанавливать зависимости не нужно.

> **plotly.js (раздел «Отчёты»)** — библиотека plotly.js v4.3.0 используется в виде
> файла проекта <code>public/vendor/plotly.min.js</code>: в работе ни npm, ни CDN не нужны,
> проект можно переносить на другой компьютер вместе с папкой. Если файла ещё нет,
> сервер скачает его **автоматически при первом запуске** (разовое действие, нужен интернет);
> вручную: <code>node tools/fetch-plotly.js</code>. Дальше «Отчёты» работают и без сети.

```bash
cd stufftime
node server.js
```

В консоли:

```
  🗒  Garbege stUff — журнал учёта рабочего времени
  локально:   http://localhost:8080
  по сети:    http://<IP-этого-компьютера>:8080
  данные:     /путь/к/stufftime/data/database.json
```

| Откуда | Адрес |
|---|---|
| С сервера | `http://localhost:8080` |
| С другой машины | `http://<IP-сервера>:8080` (откройте порт, см. ниже) |

### Доступ из сети (порт 8080)

- **Windows (admin):**
  ```bat
  netsh advfirewall firewall add rule name="stufftime" dir=in action=allow protocol=TCP localport=8080
  ```
- **Linux (ufw):**
  ```bash
  sudo ufw allow 8080/tcp
  ```

## plotly.js — библиотека для отчётов

Раздел «Отчёты» (столбчатые диаграммы: часы по дням недели и по сотрудникам) работает на библиотеке **plotly.js** — JavaScript-библиотеке для создания интерактивных графиков и диаграмм.

- Репозиторий: [plotly/plotly.js](https://github.com/plotly/plotly.js)
- В проекте plotly.js используется файлом <code>public/vendor/plotly.min.js</code> (v4.3.0) — без npm и без CDN; если файла нет, сервер скачает его при первом запуске, либо вручную: `node tools/fetch-plotly.js`.

## API (JSON)

Помимо публичных маршрутов входа (`/api/health`, `/api/login`, `/api/login/employees`), все остальные `/api/*` требуют заголовок `Authorization: Bearer <token>`, где токен выдаёт `/api/login`.

Роли (проверяются на сервере): **администратор** — полный доступ (включая архивные записи); **исполнитель** — видит и изменяет только собственные записи, вносит новые только за себя, управление справочником получает 403; **архивные записи** (дата на `archive_day` и более дней раньше текущей) — добавлять, редактировать и удалять может только администратор; **будущие даты** (позже текущей) — добавление записей и перенос на них запрещены для всех пользователей.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/employees` | справочник сотрудников |
| `POST` | `/api/employees` | внести сотрудника `{ "name", "role", "accessRole", "avatar"?, "password"? }` |
| `PUT` | `/api/employees/:id` | отредактировать (пустой `password` = не менять; `avatar` — файл из `public/avatars` или пусто; `clearPassword: true` = сбросить) |
| `GET` | `/api/avatars` | список готовых аватарок из `public/avatars` |
| `DELETE` | `/api/employees/:id` | удалить |
| `GET` | `/api/projects` | список проектов — все авторизованные (управление — только администратор) |
| `POST` | `/api/projects` | новый проект `{ "name", "description"? }` — номер присваивается автоматически, первый свободный (только администратор) |
| `PUT` | `/api/projects/:id` | отредактировать проект (только администратор) |
| `DELETE` | `/api/projects/:id` | удалить проект (только администратор) |
| `POST` | `/api/login` | вход: `{ "employeeId", "password" }` → `{ "token" }`; если пароля ещё нет — установка: `"setup": true` |
| `GET` | `/api/login/employees` | список сотрудников для экрана входа |
| `POST` | `/api/logout` | завершить сессию (нужен токен) |
| `GET` | `/api/whoami` | текущий пользователь (нужен токен) |
| `GET` | `/api/entries` | записи журнала (новые сверху) |
| `POST` | `/api/entries` | новая запись `{ date, employeeId, task, hours, comment }` (суммарно за день на одного сотрудника — не более 24 ч; архивная дата — только администратор; дата позже текущей — запрещено для всех) |
| `PUT` | `/api/entries/:id` | корректировка записи (запись в архиве и перенос на архивную дату — только администратор; перенос на будущую дату — запрещено для всех) |
| `DELETE` | `/api/entries/:id` | удалить запись (запись в архиве — только администратор) |
| `POST` | `/api/print` | печать: таблица «Задачи» за выбранную неделю → `temporary/raport.csv` + поле `csv` в ответе — браузер предлагает скачать файл на компьютер |
| `GET` | `/api/stats` | сводка (записи, часы сегодня/в месяце) |
| `GET` | `/api/health` | статус сервера |
| `GET` | `/api/setup` | настройки приложения (data/setup.json: переменные version и archive_day) — публично |

Задача в записи журнала (`task`) обязана совпадать с наименованием какого-либо проекта — иначе сервер ответит 400: «задачу можно выбрать только из справочника «Проекты»».

Пример:

```bash
curl http://localhost:8080/api/stats
```

## Первый вход

При первом запуске создаются демо-сотрудники — у всех пароль **1234**, **Енот — администратор** (пароль **12345**, аватар `raccoon`), остальные — исполнители.

В уже существующей базе роли проставляются автоматически один раз: сотрудник **Енот** становится администратором, остальные — исполнителями. Администратор по умолчанию раньше создавался как «Иванов Сергей» — при первом запуске после обновления он автоматически заменяется на **Енот** (имя, пароль 12345, аватар `raccoon`). Поменять роль можно в справочнике (✎ → «Роль доступа»); новые сотрудники создаются с выбранной ролью.
Если у сотрудника пароль ещё не задан, его можно установить прямо на экране входа (выбрать сотрудника → «Задайте пароль») — так можно раздать пароли уже существующим сотрудникам. Дальше пароль меняется в справочнике (кнопка ✎), а вход — только по нему. Сессия живёт 8 часов; кнопка «Выйти» завершает её. Токен хранится в sessionStorage браузера (исчезает при закрытии вкладки).

## Данные и сброс

Данные — обычные JSON-файлы в `stufftime/data/`:

- `database.json` — журнал записей и сессии (файл раньше назывался `stufftime.json`; при запуске сервер сам переименовывает старый файл);
- `employees.json` — справочник сотрудников (отдельный файл). При первом запуске после обновления старый справочник из `stufftime.json` переносится сюда автоматически, а сотрудникам без аватара выдаются аватары из готового набора;
- `projects.json` — справочник проектов (задач): номер (присваивается автоматически — первый свободный), наименование (уникальное), комментарий. Создаётся при первом запуске; при первом запуске с демо-данными в него попадают 6 проектов, названия которых совпадают с демо-записями журнала.
- `setup.json` — JSON-файл настроек приложения: переменная `version` (значение 1.1), настройка `archive_day` (значение 8 — архив записей) и место для будущих настроек. Создаётся автоматически при первом запуске, если файла нет; версия выводится внизу страницы как «Garbege stUff ver …» и в шапке как «Производственный журнал · рег. № …».
- `temporary/` — папка временных файлов: сюда кнопка «Печать» (вкладка «Задачи») сохраняет `raport.csv` — таблицу записей выбранной недели (браузер одновременно предлагает скачать этот файл на компьютер).

- **Сброс к демо-данным:** остановите сервер и удалите файлы `data/database.json`, `data/employees.json` и `data/projects.json`.
- **Резервная копия:** скопируйте эти файлы.

## Аватарки

Готовые аватарки лежат в `public/avatars/` (сейчас 7 шт., SVG — в том числе енот `raccoon.svg`). Список формируется сервером автоматически — положите в папку свои картинки (`.svg`, `.png`, `.jpg`, `.gif`, `.webp`) и они появятся в выпадающем списке при внесении/редактировании сотрудника. Сервер отдаёт их как `http://…:8080/avatars/имя_файла`.

## Если браузер говорит «страница не найдена»

1. **Порт занят.** Чаще всего на порту уже работает другая программа — она и отвечает
   «не найдено». Сервер Garbege stUff при запуске на занятый порт сразу напишет об этом
   в консоли и предложит: `PORT=8081 node server.js`.
2. **Запущен не тот сервер.** Убедитесь, что команда выполняется в папке `stufftime`:
   `cd stufftime && node server.js`. Если `public/index.html` не найден рядом с
   `server.js`, сервер честно напишет об этом в консоли и не запускается.
3. **Открыт не тот адрес.** Локальный адрес — `http://localhost:8080` (не 3000 —
   это порт прежнего приложения).

## Эксплуатация в production (по желанию)

- Автозапуск: `pm2 start server.js --name stufftime` или systemd-юнит (Linux).
- HTTPS: nginx / Caddy reverse-proxy перед портом 8080.
- При росте данных — заменить JSON-файл на SQLite/PostgreSQL; REST-контракт не меняется.
