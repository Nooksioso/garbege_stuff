# Garbege stUff — What's New

История изменений приложения **Garbege stUff** (учёт рабочего времени сотрудников).
Версия приложения — переменная `version` в файле настроек `data/setup.json`.

## Версия 0.7

- Новая строка в журнале: поле «Сотрудник» теперь по умолчанию заполняется данными текущей учётной записи (под которой выполнен вход в систему) — и для администратора, и для исполнителя; администратор при необходимости может выбрать другого сотрудника из списка.
- Выбор задачи: если из списка уже выбран вариант, при повторном вызове списка (поле «Задача») фильтр очищается и отображаются все проекты из справочника «Проекты»; как только пользователь начинает вводить текст — снова работает поиск по наименованию или номеру.
- Таблица «Задачи»: при выводе задач нескольких сотрудников строки группируются по Сотрудникам — строка-заголовок на каждого сотрудника (группы по алфавиту, с количеством записей), внутри группы — по дате (сначала новые); при выводе одного сотрудника таблица остаётся в обычном порядке (по дате).
- Значение переменной `version` в `data/setup.json` повышено: `0.6` → `0.7` (значения по умолчанию в `server.js` обновлены; «Garbege stUff ver 0.7»).
- Обновлена документация (README): раздел «Возможности» (пункты «Добавление строк», «Задача — только из справочника «Проекты»», новый пункт «Группировка строк по сотрудникам»), ссылки на версию приведены к 0.7.

## Версия 0.6

- Исправлено сохранение строки в таблице «Задачи»: раньше после попытки сохранить строку с ошибкой в любом поле (пустая задача, неверные часы и т.п.) кнопка ✓ в строке оставалась заблокированной — сохранить исправленную строку (кнопкой ✓ или клавишей Enter) было невозможно, а новую строку создать — только после удаления текущей. Теперь при ошибке проверки кнопка снова становится активной: как только все поля исправлены, строку можно сохранить — работают и кнопка ✓, и Enter.
- Значение переменной `version` в `data/setup.json` повышено: `0.5` → `0.6` (значения по умолчанию в `server.js` обновлены; «Garbege stUff ver 0.6»).
- Обновлена документация (README): ссылки на версию приведены к 0.6.

## Версия 0.5

- Установлен запрет на **добавление** записей с датой позже текущей — для всех пользователей, включая администратора: сервер отвечает ошибкой (400), в интерфейсе — подсказка.
- Запрет распространяется и на перенос существующей записи на будущую дату (корректировка записи — только на текущую или прошедшую дату).
- В форме записи поле «Дата» ограничено календарём текущей датой: будущие даты не выбираются в календаре браузера.
- Значение переменной `version` в `data/setup.json` повышено: `0.4` → `0.5` (значения по умолчанию в `server.js` обновлены; «Garbege stUff ver 0.5»).
- Обновлена документация: раздел «Возможности» (пункт «Записи только за прошедшие даты»), таблица API (POST/PUT `/api/entries`), структура проекта, «Данные и сброс».

## Версия 0.4

- Создана папка `temporary/` для временных файлов (печать: `raport.csv`).
- В папку `public/avatars` добавлена аватарка с енотом в общем стиле набора — `raccoon.svg` (7 шт. всего).
- Переименован файл журнала: `data/stufftime.json` → `data/database.json` (при запуске сервер сам переносит старый файл, если он ещё остался).
- Установлен запрет на **добавление** записей с датой, раньше на `archive_day` и более дней чем текущая дата, для всех, кроме администратора (сервер отвечает ошибкой, в интерфейсе — подсказка); теперь архивные даты защищёны от добавления, редактирования и удаления для не-администраторов.
- В шапке приложения надпись «производственный журнал · рег. № 001» заменена на «**Производственный журнал · рег. № 0.4**» — номер берётся из переменной `version` файла `data/setup.json`.
- На вкладке «Задачи» добавлена кнопка **🖨️ Печать**: при нажатии сервер создаёт файл `temporary/raport.csv` со всей информацией таблицы записей выбранной недели (CSV: дата, сотрудник, задача, часы, комментарий; UTF-8 с BOM). Администратор печатает все записи недели, исполнитель — только свои. Новый API: `POST /api/print`.
- Заменён администратор по умолчанию: вместо «Иванов Сергей» создаётся **Енот** (пароль **12345**, аватар `raccoon`). Для существующих баз при первом запуске после обновления выполняется разовая миграция: «Иванов Сергей» автоматически заменяется на «Енот».
- Значение переменной `version` в `data/setup.json` повышено: `0.3` → `0.4` (значения по умолчанию в `server.js` обновлены; «Garbege stUff ver 0.4»).
- Обновлена документация: раздел «Возможности» (пункты «Печать», «Архив записей», «Номер регистрации в шапке», «Роли»), структура проекта, «Данные и сброс», «Первый вход», таблица API.

## Версия 0.3

- В файл `data/setup.json` добавлена настройка `archive_day` (значение 8) — архив записей.
- Установлен запрет на редактирование (✎) и удаление (✕) записей, дата которых на `archive_day` и более дней раньше текущей даты, для всех, кроме администратора: на сервере запрос отклоняется (403), в интерфейсе кнопки неактивны, а в строке — отметка 🔒.
- Запрет также распространяется на перенос записи на архивную дату (корректировка записи с новой датой в архиве — только администратором).
- В файл README добавлено примечание: программа полностью разрабатывается моделью Claude — без привлечения органических существ, кроме енотов.
- Значение переменной `version` в `data/setup.json` повышено: `0.2` → `0.3` (значения по умолчанию в `server.js` обновлены, версия выводится внизу страницы как «Garbege stUff ver 0.3»).
- Обновлена документация: новый пункт «Архив записей» в разделе «Возможности», описание `data/setup.json` (переменные `version` и `archive_day`), таблица API (PUT/DELETE `/api/entries/:id`).
